# Isolated hopper-boundary probe (not shipped)

This is an **experimental diagnostic**, not Factory Meter. These files are outside `src` and do not affect the production JAR. To reproduce in a disposable test checkout only, copy `mixin/HopperHookMixin.java` into `src/main/java/dev/mcpfabric/neoforge/meter/`, `helper/HopperProbe.java` into `src/main/java/dev/mcpfabric/neoforge/meterprobe/`, copy `mechagent-meter.mixins.json` to `src/main/resources/`, and add a `[[mixins]]` entry for that config to the NeoForge metadata. Rebuild and launch only the isolated production-server with `-Dmechagent.meterProbe=true`; do not add the probe to a real world.

With Minecraft 1.21.1, NeoForge 21.1.248 and Create 6.0.10, a single explicitly supplied iron sheet and a five-sheet fixture produced respectively one and five `evidence_consistent` diagnostic lines on the known depot-to-vanilla-hopper path; the output chest increased by the same fixture quantities. After normal restart, one further explicitly supplied sheet produced one line. These are observations of test-supplied sheets, not measured production, persistent counters, or a complete logistics meter. Local ignored evidence: `integration-test/evidence/meter-probe-batch.log` and `meter-probe-restart.log`.

The probe has no authorization, persistent ledger, deduplication, queue/backpressure accounting, window statistics, optional-mod compatibility guarantee, full-pack validation or in-game validation of its updated reentrant-context handling. It logs evidence and silently declines ambiguous cases; it must not be used as a reliable production counter. NeoForge can return success even when the actual extraction is empty, so the probe checks the non-simulated returned stack against the destination delta and components. Further engineering and tests are required before an active adapter can be released.

One early isolated probe crashed because a non-mixin helper was placed inside the mixin-owned package; the helper was moved to a separate package before the successful tests. The isolation launcher also now refuses to start while either fixed test port is occupied; port checks are a preflight, not a cross-process lock.
