# Incremental refactor plan

This plan is a sequence of reviewable changes, not authorization to claim proposed features already exist. Baseline: branch `mechagent-poc01-observation`; preserve original MCP methods, MIT attribution and untracked `knowledge/` work. Existing tests and the observed isolated Create and Mechanomania runs are regression inputs, not proof of unsupported versions or crash safety. Validate each stable phase independently, including NeoForge build + Java tests, TypeScript typecheck + full MCP tests; run Fabric 1.21.1 tests when dependencies are available and explicitly report a failure to run. Record JAR hash and live-game evidence when behavior changes. Do not create an RC tag until the user's release criteria are met.

## Migration checkpoints

The baseline report records earlier full-pack observations with their artifact hash. Shared work-area parsing, per-world meter state, loader-driven adapter detection, runtime catalog exports and native moving-structure tools are implemented. The profiles and minecart fixture have dedicated script entry points.

See the [RC1 acceptance report](../reports/v1-rc1-acceptance.json) for the current moving-device, full-pack, recovery and performance results. The Java `AcceptanceFixture` has been removed from the production JAR. Keep the synchronous journal path while its measured cost is acceptable. Any later scheduler must preserve durable intent, response fields and persisted records, with equivalent fault-injection coverage.

## Acceptance gates for each migration

- **Behavior:** Existing RPC names, schemas, read-only behavior and intentionally unsupported states remain compatible. No unsupported tool is advertised as usable merely because it is registered. New response fields are additive and contracts are tested across Java and TypeScript.
- **Authority:** Keep loopback and token authentication, vision/registry gates, area validation and default-disabled broad world write/commands/player control. Test alternate entrypoints, revoked access and out-of-bounds requests. Never trade immediate correctness for an unlabelled stale policy cache.
- **Concurrency:** Every world read or mutation runs on the server thread, with loaded-chunk checks, bounded work and cancellation; no global world scan. Measure the cost of slow mod getters and ensure no cross-tick result is represented as atomic.
- **Persistence:** Keep existing data readable before changing formats. Test queue saturation, write failures, corruption, normal and abnormal restarts. Distinguish queued, persisted and force-completed; no claim of exactly once or atomic world+journal commit without a proven mechanism. Retain explicit gaps and uncertainty on rollback.
- **Verification:** Execute targeted tests, full Java/TypeScript/MCP regression for the affected loader, then the relevant isolated real-game fixture. Report separate source artifact hashes, test conditions, observed values, version coverage and remaining failures. Validate other loader compilation where feasible. Preserve upstream interfaces and run matrix builds in suitable CI rather than guessing.

## Deliberate non-goals

No large Gradle split, no mandatory shared database, no new planner/front end, no FTB Quests integration, no new unprotected write paths and no assumption that every addon implements the same capability. Structural changes must pay for themselves against actual reuse, reliability or security evidence.
